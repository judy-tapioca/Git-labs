# Отчет по лабораторной работе №5. Средства управления проектами

## Цель работы
Познакомиться с простыми техническими средствами управления проектами на основе задач (issues) и Kanban-досок.

## 1. Создание и настройка проекта

В репозитории была настроена Kanban-доска для проекта **«Курсовая работа по разработке бота»** со следующими этапами выполнения задач:

* **Backlog (Сформулировано):** Задачи определены, но ещё не запланированы.
* **Todo (К выполнению):** Задачи, запланированные на ближайшее время.
* **In Progress (В работе):** Задачи, выполняемые в данный момент.
* **In Review (На согласовании):** Работа завершена, ожидается проверка преподавателем.
* **Done (Завершено):** Полностью выполненные и принятые задачи.

### Пользовательские поля

Для обогащения информации по каждому тикету были добавлены три пользовательских поля:

1.  **Start Date (Дата начала):** Поле с датой начала работы.
2.  **End Date (Дата окончания):** Поле с датой ожидаемого завершения.
3.  **Work Type (Тип задачи):** Поле выбора: *Research* (Исследование), *Documentation* (Документация), *Programming* (Программирование).

## 4. Исследование альтернатив

Были рассмотрены системы управления проектами: **Trello**, **Jira**, **Notion** и **GitHub Projects**.

* **Trello:** Простой интерфейс Kanban-досок, удобен для малых групп, но требует Power-Up для связи с GitHub.
* **Jira:** Профессиональный инструмент Agile с мощной аналитикой, но имеет высокий порог входа.
* **Notion:** Универсальное пространство для документации и планов. Удобно для ведения заметок, но не имеет встроенной поддержки отслеживания Pull Requests и статусов веток.

**GitHub Projects** выбран как основной инструмент благодаря нативной интеграции с репозиторием. Это позволяет объединить управление кодом и задачами в одной среде и использовать технические блокировки (Blocked/Dependencies).

### Реализация процесса в Trello
В качестве альтернативы рассмотрена система Trello. Процесс организуется через доски с колонками (Сформулировано, В работе и т.д.) и цветовыми метками.
**Ограничения Trello:** отсутствие автоматического закрытия задач при слиянии PR, невозможность нативной блокировки карточек по статусу зависимых задач и отсутствие связи с ветками репозитория без сторонних плагинов.


**Результат:** Проект полностью настроен, зависимости установлены, процесс согласования запущен через систему Pull Requests.
