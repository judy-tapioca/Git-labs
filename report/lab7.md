### Риски безопасности при предоставлении доступа к VM

Предоставление доступа к виртуальной машине посторонним лицам может привести к раскрытию файлов, приложений и системных ресурсов в зависимости от предоставленных им прав доступа.

Возможный доступ включает:

**Файлы и данные:**
- Личные файлы и файлы конфигурации
- Базы данных и исходный код
- Учетные данные или SSH-ключи, если они небезопасны

**Системные ресурсы:**
- Использование ЦП и памяти
- Дисковое хранилище и сетевой доступ
- Запущенные службы и приложения

**Административный контроль:**
- Если посторонние получат права root, они смогут установить вредоносное ПО, удалить файлы, создать новые учетные записи, отслеживать активность и отключить средства защиты

**Риски безопасности включают:**
- Кража данных и заражение вредоносным ПО
- Несанкционированные изменения системы
- Использование VM для дальнейших атак

**Для снижения риска:**
- Предоставлять только минимально необходимые разрешения
- Использовать надежные пароли и SSH-ключи
- Ограничивать открытые порты с помощью брандмауэров
- Поддерживать программное обеспечение в актуальном состоянии
- Отслеживать журналы и активность доступа



## 2. Настройка удаленного доступа (SSH)

Проверено наличие SSH-клиента в Windows — клиент уже установлен по умолчанию.

### 2.1 Установка SSH-сервера

SSH-сервер не был установлен по умолчанию. Установка выполнена командой:

```bash
sudo apt install openssh-server
sudo systemctl enable ssh
sudo systemctl start ssh
sudo systemctl status ssh
```

Вывод:

```
Active: active (running)
Server listening on 0.0.0.0 port 22.
```

### 2.2 Что такое TCP-порт

**TCP-порт** — это пронумерованный коммуникационный конечный пункт, используемый приложениями и службами в компьютерной сети. TCP (Transmission Control Protocol) обеспечивает надежную и упорядоченную доставку данных между устройствами. Различные службы используют разные номера портов:

- Порт 22 — **SSH**
- Порт 80 — **HTTP**
- Порт 443 — **HTTPS**

### 2.3 Что такое проброс портов

**Проброс портов** — это сетевая технология, позволяющая перенаправлять входящий трафик на определенном порту от хост-машины к устройству внутри частной сети (виртуальной машине). Например, трафик на порту 2222 хоста перенаправляется на порт 22 виртуальной машины, на котором запущен SSH.

### 2.4 Настройка проброса портов в VirtualBox

В настройках VirtualBox (Settings → Network → Adapter 1 → Advanced → Port Forwarding) добавлено правило:

| Name | Protocol | Host IP | Host Port | Guest IP | Guest Port |
|------|----------|---------|-----------|----------|------------|
| SSH  | TCP      |         | 2222      |          | 22         |

### 2.5 Подключение к VM по паролю

```
ssh judy@127.0.0.1 -p 2222
```

Подключение выполнено успешно.

### 2.6 Генерация SSH-ключей

На Windows-хосте сгенерирована пара ключей:

```
ssh-keygen
```

- Приватный ключ: `C:\Users\Judy Banda\.ssh\id_ed25519`
- Публичный ключ: `C:\Users\Judy Banda\.ssh\id_ed25519.pub`

### 2.7 Добавление публичного ключа на VM

```bash
type "C:\Users\Judy Banda\.ssh\id_ed25519.pub" | ssh -p 2222 judy@127.0.0.1 "cat >> ~/.ssh/authorized_keys"
chmod 600 ~/.ssh/authorized_keys
```

### 2.8 Проверка подключения без пароля

```
ssh -p 2222 judy@127.0.0.1
Welcome to Ubuntu 24.04.4 LTS
judy@judy-virtualbox:~$
```

Подключение выполнено без запроса пароля.

### 2.9 Отключение аутентификации по паролю

В файле `/etc/ssh/sshd_config` изменены настройки:

```
PasswordAuthentication no
PubkeyAuthentication yes
```

```bash

```

### 4.4 Клонирование репозитория

Использовалось клонирование по HTTPS с персональным токеном доступа GitHub (PAT).

**Почему не использовался SSH-ключ?**

Размещение приватного SSH-ключа на чужой машине крайне опасно:
- Владелец компьютера может украсть ключ и использовать его для доступа к аккаунтам
- Если компьютер взломан, злоумышленник получит полный доступ ко всему
- После размещения на чужой машине невозможно контролировать использование ключа
- Приватный ключ подобен паролю — его никогда нельзя размещать на чужой машине

Поэтому использован HTTPS с персональным токеном доступа (PAT), который можно отозвать в любой момент.

```bash
git clone https://github.com/judy-tapioca/Data-structures
Cloning into 'Data-structures'...
Receiving objects: 100% (77/77), 278.95 KiB | 384.00 KiB/s, done.
```
