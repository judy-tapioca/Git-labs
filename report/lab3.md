### Visual Studio Community в качестве альтернативной среды разработки

Ранее в течение примерно двух месяцев я использовала **Visual Studio Community** в качестве основной среды разработки, однако позже перешёл на **VS Code**.

По моему мнению, **VS Code** оказался более удобным вариантом, особенно для начинающего программиста. Интерфейс программы проще и понятнее, а основные функции доступны без сложной настройки. Также VS Code хорошо подходит для обучения, так как позволяет легко работать со встроенным терминалом и лучше понимать выполнение команд и процессы сборки проекта.

**Visual Studio Community** предоставляет больше встроенных инструментов и возможностей, однако для новичка она может показаться слишком сложной и перегруженной. Поэтому в итоге я выбрала **VS Code**, так как он удобнее для обучения и повседневной работы.

### Вывод

В ходе работы я ознакомился с различными инструментами разработки и попробовал альтернативные программы для выполнения одних и тех же задач. На практике я сравнил Visual Studio Community и VS Code и пришёл к выводу, что для начинающего разработчика VS Code является более удобным решением благодаря простому интерфейсу и лёгкой настройке.

Также я убедился, что правильная настройка среды разработки (темы, шрифты, горячие клавиши, терминал и интеграция с Git) значительно повышает удобство работы и ускоряет процесс разработки.

### PowerShell в качестве альтернативной командной оболочки

В течение недели я использовала **PowerShell** в качестве основного терминала, однако в итоге вернулся к **Git Bash**, так как он оказался для меня более удобным.

PowerShell хорошо интегрирован в Windows и подходит для системных задач, но его команды и синтаксис отличаются от привычных Linux-команд. Git Bash, наоборот, предоставляет более понятную и привычную Unix-подобную среду, где используются стандартные команды (`ls`, `cd`, `pwd` и др.).

Кроме того, Git Bash удобнее при работе с Git, так как большинство примеров и инструкций в интернете рассчитаны именно на bash-команды. Поэтому я считаю, что **Git Bash является более удобным вариантом**, особенно для обучения и повседневной разработки.

### Настройка приглашения командной строки (Bash / Git Bash)

Приглашение настраивается через переменную `PS1` в файле `~/.bashrc`.  
Чтобы открыть файл для редактирования:

```bash
nano ~/.bashrc
```

После изменений применить без перезапуска терминала:

```bash
source ~/.bashrc
```

**Что можно выводить:**

| Код | Описание |
|-----|----------|
| `\u` | Имя пользователя |
| `\h` | Имя хоста |
| `\W` | Последняя папка пути (сокращённый путь) |
| `\w` | Полный путь к директории |
| `\t` | Текущее время `HH:MM:SS` |
| `\d` | Текущая дата |
| `$( git branch ... )` | Активная ветка Git |

**Конфигурация `~/.bashrc`:**

```bash
parse_git_branch() {
  git branch 2>/dev/null | grep '*' | sed 's/* //'
}

 PS1='\[\e[90m\]\t \[\e[36m\]\W\[\e[33m\]$(b=$(parse_git_branch); [ -n "$b" ] && echo " ($b)")\[\e[0m\] $ '
```

## 1. Полезные горячие клавиши

### Как открыть настройки горячих клавиш в VS Code

Открыть список горячих клавиш (Keyboard Shortcuts) можно двумя способами:

- С помощью клавиатуры: `Ctrl + K`, затем `Ctrl + S`
- Через меню: `File → Preferences → Keyboard Shortcuts`

| Горячая клавиша | Действие |
|----------|--------|
| `Ctrl + Enter` | Вставить новую строку ниже и перейти на неё |
| `Ctrl + Shift + Enter` | Вставить новую строку выше и перейти на неё |
| `Alt + ↑ / ↓` | Переместить текущую строку вверх или вниз |
| `Shift + Alt + ↓` | Дублировать текущую строку ниже |
| `Ctrl + Shift + K` | Удалить текущую строку |
| `Ctrl + D` | Выделить следующее вхождение текущего слова |
| `Alt + Click` | Добавить несколько курсоров |
| `Ctrl + Z` | Отменить последнее действие |
| `Ctrl + /` | Закомментировать / раскомментировать строку |



## 2. Навигация и редактирование

### Поиск по содержимому файлов
- `Ctrl + Shift + F` — поиск по всем файлам проекта
- Введите ключевое слово, и VS Code покажет каждый файл и строку, где оно встречается
- Можно фильтровать по типу файла или папке

### Перейти к объявлению
- `F12` — перейти к месту, где функция или переменная была **объявлена**
- Правая кнопка мыши → **Go to Definition**

### Перейти к реализации
- `Ctrl + F12` — перейти к месту, где написана фактическая **логика/код** функции
- Правая кнопка мыши → **Go to Implementation**

### Найти все места использования
- `Shift + F12` — найти все места в проекте, где переменная,
  функция или тип **используется**
- Правая кнопка мыши → **Find All References**

### Переименовать все вхождения
- `F2` — безопасно переименовать переменную или функцию **везде**, где она встречается
  в проекте
- Правая кнопка мыши → **Rename Symbol**

### Быстрая навигация между местами кода
- `Ctrl + Tab` — переключение между недавно открытыми файлами
- `Ctrl + P` — быстро открыть любой файл по имени
- `Ctrl + G` — перейти к определённому номеру строки
- `Ctrl + Shift + O` — перейти к любой функции или символу в текущем файле
- `Alt + ← / →` — назад / вперёд к предыдущим позициям курсора

### Комментирование и раскомментирование больших блоков
- `Ctrl + /` — закомментировать / раскомментировать выделенные строки
- `Shift + Alt + A` — блочный комментарий для нескольких строк
- Сначала выделите несколько строк, затем нажмите горячую клавишу,
  чтобы закомментировать их все сразу

## 5. Кастомизация процессов

### 1. Что такое горячие клавиши в IDE и как их настраивать

Горячие клавиши (*keyboard shortcuts*) — это сочетания клавиш, которые позволяют выполнять команды редактора или запускать пользовательские задачи (*tasks*) без использования мыши. Это ускоряет работу и делает процесс разработки более удобным.

В **Visual Studio Code** механизм настройки горячих клавиш и автоматизации процессов реализован на трёх уровнях:

| Уровень | Файл | Назначение |
|--------|------|------------|
| Глобальные команды | `keybindings.json` | Настройка стандартных команд редактора |
| Задачи проекта | `.vscode/tasks.json` | Пользовательские команды сборки и тестирования |
| Запуск/отладка | `.vscode/launch.json` | Конфигурации запуска и отладки программы |



### 2. Как открыть редактор горячих клавиш

Для настройки сочетаний клавиш в VS Code можно использовать интерфейс программы или редактировать JSON-файл напрямую.

**Через интерфейс (UI):**
- `File → Preferences → Keyboard Shortcuts`
- или сочетание клавиш `Ctrl + K`, затем `Ctrl + S`

**Через JSON-файл:**
- открыть палитру команд `Ctrl + Shift + P`
- выбрать команду: **Open Keyboard Shortcuts (JSON)**

После этого открывается файл `keybindings.json`, в котором можно задавать собственные сочетания клавиш.



### 3. Настройка автоматизации процессов (Build / Debug / Tests)

Для упрощения работы в VS Code можно настроить запуск основных процессов разработки через **Tasks** и привязать их к горячим клавишам.

#### Сборка проекта (Build)

Сборка проекта настраивается через файл `.vscode/tasks.json`, в который добавляется команда сборки.  
После настройки сборку можно запускать через меню или горячую клавишу.
```json
{
  "version": "2.0.0",
  "tasks": [
    {
      "label": "Build Windows (g++)",
      "type": "shell",
      "command": "cmd",
      "args": [
        "/c",
        "g++ -g *.cpp -o lab2.exe"
      ],
      "options": {
        "cwd": "${workspaceFolder}"
      },
      "group": {
        "kind": "build",
        "isDefault": true
      },
      "problemMatcher": []
    },
    {
      "label": "Build WSL (Linux)",
      "type": "shell",
      "command": "wsl",
      "args": [
        "g++",
        "-g",
        "*.cpp",
        "-o",
        "lab2.out"
      ],
      "options": {
        "cwd": "${workspaceFolder}"
      },
      "group": "build",
      "problemMatcher": []
    },
    {
      "label": "Build Release (Windows)",
      "type": "shell",
      "command": "cmd",
      "args": [
        "/c",
        "g++ -O2 *.cpp -o lab2_release.exe"
      ],
      "options": {
        "cwd": "${workspaceFolder}"
      },
      "group": "build",
      "problemMatcher": []
    },
    {
      "label": "Run Tests",
      "type": "shell",
      "command": "${workspaceFolder}/lab2.exe",
      "args": [
        "--test"
      ],
      "dependsOn": "Build Windows (g++)",
      "problemMatcher": []
    }
  ]
}
```

#### Запуск и отладка программы (Debug / Run)

Для запуска программы в режиме отладки используется файл `.vscode/launch.json`.  
Этот файл хранит конфигурации запуска и позволяет запускать программу с отладчиком нажатием `F5` или `Fn + F5`.

```json
{
  "version": "0.2.0",
  "configurations": [
    {
      "name": "Debug on Windows",
      "type": "cppdbg",
      "request": "launch",
      "program": "${workspaceFolder}/lab2.exe",
      "args": [],
      "stopAtEntry": false,
      "cwd": "${workspaceFolder}",
      "preLaunchTask": "Build Windows (g++)",
      "MIMode": "gdb",
      "miDebuggerPath": "C:\\msys64\\mingw64\\bin\\gdb.exe",
      "externalConsole": false
    }
  ]
}
```
#### Запуск автоматических тестов

Автоматическое тестирование также настраивается через `.vscode/tasks.json`, где задаётся команда запуска тестов (например `pytest`, `npm test`, `ctest` и т.д.).

```json
{
  "label": "Run Tests",
  "type": "shell",
  "command": "${workspaceFolder}/lab2.exe",
  "args": [
    "--test"
  ],
  "dependsOn": "Build Windows (g++)",
  "problemMatcher": []
}
```

### Почему я использовал `cmd` в задаче сборки

При настройке сборки проекта в VS Code я заметил, что в Windows терминал PowerShell не всегда корректно обрабатывает шаблон `*.cpp` (иногда компилятор `g++` не видит файлы).  
Чтобы избежать этой проблемы, я настроила задачу сборки через `cmd` (Windows Command Prompt), так как он правильно разворачивает `*.cpp` в список исходных файлов и сборка выполняется стабильно.

## 7. Интеграция с Git (VS Code)

VS Code имеет встроенную Git-интеграцию — дополнительная установка не требуется.  
Открыть панель управления Git: `Ctrl + Shift + G`



#### Просмотр изменений

`Ctrl + Shift + G` — открывает список всех изменённых файлов.  
Клик на любой файл — открывается diff-просмотр: слева старая версия.
Изменённые файлы помечаются в Explorer буквами: `M` — modified, `U` — untracked, `D` — deleted.



#### Добавление файлов в индекс (Stage)

В панели `Ctrl + Shift + G` навести на нужный файл → нажать `+` рядом с ним.  
Чтобы добавить все файлы сразу — нажать `+` рядом с заголовком *Changes*.



#### Коммит

В панели `Ctrl + Shift + G` ввести сообщение в поле сверху → нажать `Ctrl + Enter`.



#### Добавление удалённого репозитория

`Ctrl + Shift + G` → `...` → *Remote* → *Add Remote* → вставить ссылку на репозиторий и задать имя (обычно `origin`).



#### Получение обновлений (Pull)

`Ctrl + Shift + G` → `...` → *Pull*  
или кликнуть на иконку синхронизации `↓` в строке состояния внизу экрана.



#### Отправка обновлений (Push)

`Ctrl + Shift + G` → `...` → *Push*  
или кликнуть на иконку синхронизации `↑` в строке состояния внизу экрана.



#### Разрешение конфликтов

При конфликте VS Code автоматически выделяет проблемные места в файле и предлагает варианты:

| Кнопка | Действие |
|--------|----------|
| *Accept Current Change* | Оставить вашу версию |
| *Accept Incoming Change* | Принять версию из удалённого репозитория |
| *Accept Both Changes* | Оставить обе версии |
| *Compare Changes* | Сравнить вручную |

После выбора — сохранить файл, затем добавить в индекс и сделать коммит через `Ctrl + Shift + G`.
